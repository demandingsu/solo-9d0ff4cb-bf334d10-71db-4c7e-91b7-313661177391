# 采购标段截标时间核验工具

面向投标专员的网页工具：输入公告列表页地址、项目编号、标段号，沿分页抓取原公告、延期公告和终止公告，按发布时间合并出该标段当前有效的投标截止时间。

另附**清单差异页**：采购代理人输入同站旧版、新版公告详情地址，工具读取两页 HTML 需求表，还原合并单元格中的包号，按“包号 + 品目号”对齐名称、数量和单位，列出新增、删除、修改与待核项，便于通知已领取文件的供应商。

应用使用 Python FastAPI，连同本地公告示例站通过 Docker Compose 启动。示例站为纯本地数据，**构建镜像后整个演示不需要访问互联网**。

## 启动

```bash
docker compose up --build
```

- 核验工具：<http://localhost:8000>
- 清单差异页：<http://localhost:8000/diff>
- 本地公告示例站：<http://localhost:8001/notices?page=1>
- OpenAPI：<http://localhost:8000/docs>

首次启动会下载 Python 镜像与依赖；镜像构建完成后，核验、翻页、查看来源链接都在本机完成，可断网演示。

停止：

```bash
docker compose down
```

## 演示用例

首页已提供一键示例：

| 用例 | 项目编号 | 标段 | 预期 |
| --- | --- | --- | --- |
| 投标进行中（已延期） | `DEMO-2026-001` | `02` | 有效截止时间 `2026-11-12 09:30`，来源为第 2 页延期公告 |
| 已终止 | `DEMO-2026-001` | `01` | 状态“已终止”，**不显示有效截止时间**；时间线保留原公告、延期、终止三次变化及各自来源 |
| 不同编号格式 | `DEMO-2026-002` | `A` | 有效截止时间 `2026-11-25 14:00`；A 包的成交结果公告不改变截止时间 |

清单差异页（`/diff`）也提供一键示例：

| 用例 | 旧版 → 新版 | 预期 |
| --- | --- | --- |
| 需求更正（合并包号 · 换包） | `DEMO-2026-004` 第 1 版 → 第 2 版需求表 | 包号合并单元格被还原；修改 1 项（台式计算机 50→60 台）；删除 2 项（含换出的激光打印机）；新增 2 项（含换入包 2 的激光打印机与扫描仪）；行顺序变化不计 |
| 单版内容冲突（待核） | `DEMO-2026-005` 第 1 版 → 第 2 版需求表 | 新版中包 1 品目 2 出现两行且数量冲突，仅该品目标为待核；订书机 100→120 个仍计为修改；不从冲突行推断增删 |

示例数据故意分布在第 1、2、3 页：`DEMO-2026-001` 的原公告在第 1 页，01 标段延期在第 2 页，终止在第 3 页；同项目 02 标段也有自己的公告，核对 01 标段时不会被混入。需求表示例公告在第 4–5 页。

示例站也可以在宿主机通过 <http://localhost:8001/notices?page=1> 直接浏览。工具内预填示例地址 `http://localhost:8001/notices?page=1`；即使应用与示例站分处不同容器，工具也能识别这个公开地址并转到容器内网抓取。核验结果中的所有来源链接会自动转成 `http://localhost:8000/demo/...` 代理链接，因此浏览器也可直接打开。

## 核验规则

1. **分页发现**：从列表页开始，沿 `rel=next`、分页器内的页码/下一页链接继续抓取，直到没有更多页或达到安全上限。
2. **精确匹配标段**：只有详情页中项目编号和目标标段号同时匹配才纳入合并。列表页有明确项目/标段信息时会先排除其他项目和其他标段，详情页仍会再次校验，避免混入同项目其他标段。
3. **按发布时间排序**：将命中的原公告、延期/更正公告、终止公告按详情页发布时间合并。
4. **只应用明确修改**：延期公告只有载明新的投标截止时间时才替换旧时间；页面只是引用旧时间、或只说“另行通知”而没有新时间时，结论为“无法判定”，不会把旧时间继续当作有效时间。
   - 同时支持“原时间……现延期至……”“……变更为……”“变更后：……”等写法，避免把“原时间”误当新时间，也不会把开标时间误当投标截止时间。
5. **终止优先**：一旦终止公告发布，状态固定为“已终止（不再接受投标）”，有效截止时间为空，旧时间只出现在历史时间线中并明确标注失效。
6. **失败即无法判定**：列表页、分页页、候选详情页抓取失败，详情页关键字段无法解析，缺少原公告，或相关公告缺少发布时间导致无法排序时，页面显示“无法判定”和失败/检索地址，并置空有效截止时间。**不会沿用之前的查询结果**。
7. **无缓存**：每次查询都实时重新抓取，不保存、不读取旧结论。

其他公告（如成交结果公告）可以出现在命中的公告列表中，但不会改变标段状态或截止时间。

## 清单差异规则

1. **同站两地址**：输入同一站点的旧版、新版公告详情页地址；两地址不同站时本轮不予比较。
2. **读取需求表**：在页面中识别含“品目号、名称、数量、单位”列的表格；找不到需求表视为该页读取失败。
3. **还原合并单元格**：展开 `rowspan`/`colspan`，被合并的包号回填到每一行；包号留空的行沿用上一行包号。整行合并的标题行、备注行不计入数据行。
4. **按键对齐**：以“包号 + 品目号”为键对齐两版数据行，比较名称、数量、单位；行顺序变化不算修改。
5. **换包即增删**：品目换包按旧包删除、新包新增处理。
6. **单版冲突仅待核**：同一版本内同键重复且内容冲突时，仅将该品目标为待核，其余品目继续比较，不从冲突行推断增删；重复但内容一致的行按一行处理并给出提示。
7. **失败不给结论**：任一页面抓取或解析失败时，页面只列出失败地址，不提供本轮确定差异。每次比较都实时抓取，无缓存。

## JSON API

```bash
curl -G http://localhost:8000/api/check \
  --data-urlencode 'list_url=http://localhost:8001/notices?page=1' \
  --data-urlencode 'project_no=DEMO-2026-001' \
  --data-urlencode 'section_no=01'
```

也支持 `POST /api/check`：

```json
{
  "list_url": "http://localhost:8001/notices?page=1",
  "project_no": "DEMO-2026-001",
  "section_no": "01"
}
```

关键返回字段：

- `status`：`ongoing` / `extended` / `terminated` / `unknown`
- `determinable`：是否有足够证据形成结论
- `effective_deadline`：当前有效截止时间；终止或无法判定时为 `null`
- `deadline_source_url`：当前结论来源链接
- `changes`：按发布时间排列的变化记录，每条都带 `url`
- `failures`：抓取/解析失败地址及原因
- `notices`：命中的目标标段公告（不包含其他标段）

清单差异接口：

```bash
curl -G http://localhost:8000/api/diff \
  --data-urlencode 'old_url=http://localhost:8001/notices/detail/DEMO-2026-004-req-v1' \
  --data-urlencode 'new_url=http://localhost:8001/notices/detail/DEMO-2026-004-req-v2'
```

也支持 `POST /api/diff`（JSON 体 `{"old_url": "...", "new_url": "..."}`）。关键返回字段：

- `determinable`：两页是否都成功读取；为 `false` 时 `failures` 给出失败地址，差异列表为空
- `summary`：新增 / 删除 / 修改 / 待核 / 未变化数量
- `added`、`removed`：差异品目原文及来源地址
- `modified`：逐项字段变化（旧值 → 新值）及两边原文、来源
- `pending`：待核品目在两版中的全部行及冲突原因
- `old_page` / `new_page`：两页标题与读取行数

## 本地测试

不启动容器也可运行解析与合并规则测试（需要先安装 `requirements.txt`）：

```bash
python -m unittest discover -s tests -v
```

测试使用 `httpx.MockTransport`，覆盖跨页、延期替换、终止失效、同项目其他标段隔离、详情页失败、缺少原公告和“无新时间的延期”等场景；清单差异测试覆盖合并包号还原、行顺序忽略、换包增删、单版冲突待核、整行合并的标题/备注行跳过和读取失败不给结论等场景。

## 边界与限制

- 只抓取 HTTP/HTTPS 的 HTML 页面；链接限定在输入列表页同一站点（scheme + host），不会跟随站外跳转。
- 单次查询设置列表页/详情页数量和响应大小上限，避免误抓大型站点；超过上限时结论为“无法判定”而不是猜测。
- 不处理需要登录、验证码、JavaScript 动态渲染的公告站。
- 日期按页面原始时区文本解析（示例为北京时间），不进行时区换算。
- 清单差异只比较页面 HTML 中可见的需求表文本，不比对附件（Word/PDF）内容；同一页面有多张含品目列的表格时会合并读取。
- 示例站数据均为虚构，不代表任何真实采购项目。
